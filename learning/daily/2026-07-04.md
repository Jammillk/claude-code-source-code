## 核心理解

### 1. API 对接的三个层次

| 层次 | 代码 | 职责 |
|------|------|------|
| 读取密钥 | `load_config()` → `config.json` | 从配置文件拿到 `api_key` |
| 建连接 | `OpenAI(api_key=..., base_url=...)` | 创建 HTTP 客户端 |
| 发请求 | `client.chat.completions.create(...)` | 把 messages[] + tools 发过去 |

### 2. API 返回结构

```python
response = {
    "choices": [{              # 数组，默认长度=1（n=1）
        "index": 0,
        "message": {           # 模型回答
            "role": "assistant",
            "content": "...",      # 文字（可能 null）
            "tool_calls": [...]    # 工具调用（可能 null）
        },
        "finish_reason": "stop"  # 为什么停了
    }],
    "usage": { ... }
}
```

`choices[0]` 是因为 API 支持 `n=3` 一次出多个答案（投票/对比），默认 `n=1`。

### 3. `finish_reason` 的机制

**不是 prompt 里写的，是 API 服务器检测模型输出后自动返回的。**

模型训练时被植入了特殊 token（如 `<|endoftext|>`），API 服务器检测到这些 token 后分类设置 finish_reason：

| 值 | 触发 | 处理 |
|----|------|------|
| `"stop"` | 输出结束 token | 退出循环 |
| `"tool_calls"` | 输出工具调用格式 | 执行工具 → 继续循环 |
| `"length"` | 达到 max_tokens 上限 | 可继续追问 |
| `"content_filter"` | 安全审核触发 | 报错退出 |

我们代码做的事：**根据 finish_reason 决定下一步**，这就是 Agent 循环的本质。

### 4. messages[] 会越积越多 — 这是 Agent 的核心难题

```
第 1 轮: 400 tokens
第 2 轮: 800 tokens
...
第 N 轮: 可能超模型上限
```

Claude Code 的解决方案 (`src/services/compact/`)：

- **自动摘要**：老消息压缩成一段总结
- **裁剪**：去掉僵尸消息
- **折叠**：重构上下文结构

这部分是后续学习的重点。

### 5. 核心循环代码（DeepSeek/OpenAI 版本）

```python
messages = [系统提示, 用户输入]

for turn in range(max_turns):
    response = client.chat.completions.create(messages=messages, tools=TOOLS)
    msg = response.choices[0].message

    if msg.content:
        print(msg.content)          # 显示文字

    if finish_reason == "tool_calls":
        messages.append(msg)        # 记录 assistant 消息
        for tc in msg.tool_calls:
            result = execute_tool(tc.function.name, tc.function.arguments)
            messages.append({"role":"tool", "content": result})
        # 继续循环

    elif finish_reason == "stop":
        break
```
